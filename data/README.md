# SAMPLE data corpus

Every corpus artifact in this directory is fictional and marked `SAMPLE` in its contents, record labels, or product-import CSV filename. It is for offline tests only and is not real company research or generated intelligence.

- `company_info/relaycue.md` and `company_info/fieldnest.md`: two distinct fictional products.
- `prospects/SAMPLE_relaycue.csv` and `prospects/SAMPLE_fieldnest.csv`: 13 and 12 fictional prospects, respectively. Each file uses exactly the fields in `app.prospects.CSV_FIELDS` and is directly importable for its product. `page_text_path` is repository-root-relative (for example, `data/prospect_pages/p001.txt`); the page filename links to `prospect_id` in `sample_case_notes.csv`.
- `prospect_pages/`: one labelled fictional source page per prospect, addressed with reserved `.example` domains.
- `sample_case_notes.csv`: evaluator-only annotations for poor-fit, no-signal, explicit-signal, and implied-but-not-stated cases. Do not pass this file to a workflow as prospect evidence.
- `sample_replies.json`: 20 fictional replies with ground-truth labels; 13 `development` and 7 `held_out` (35%). Held-out records are reserved and must not be used while iterating on prompts.

The records were authored as independent fictional cases before workflow prompts were implemented; they were not generated by, or tuned against, model prompts. Hard cases include poor product/buyer fit, no stated buying signal, vague language that must not be promoted to an evidence-backed signal, a polite soft no, an out-of-office message with a referral, and a pricing question embedded in a rejection.

No classification accuracy is reported yet: the reply-classification workflow and evaluator are not implemented. When they are, report held-out accuracy and per-label results from the seven reserved examples; do not describe the score as 100% or tune against those held-out labels.
